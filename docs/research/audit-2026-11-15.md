## 1. Running `video-setup.sh`

Command: `time bash -x video-setup.sh` → **exit 0, 36.3 s wall** (12.6 s user). Exit 0 is misleading: the biggest step failed.

| Step | Result | Notes |
|---|---|---|
| `pip install ... moviepy "pillow>=12.2" "scenedetect[opencv]" ...` | **FAILED — nothing installed** | `moviepy` 2.2.1 requires `pillow<12.0`; script demands `pillow>=12.2`. pip backtracks to moviepy 1.0.x sdist, whose `setup.py bdist_wheel` dies on modern setuptools (`AttributeError: install_layout`). pip aborts the whole transaction, so **opencv, librosa, scenedetect, scikit-image, colour-science, matplotlib are all absent** (`import cv2` → ModuleNotFoundError). Also `WARNING: scenedetect 0.7.3 does not provide the extra 'opencv'`. |
| Fonts (9 files from `cdn.jsdelivr.net/gh/google/fonts@main`) | OK | All 9 valid TTFs in `~/.fonts`, visible to fontconfig. `|| true` on every curl hides failures. Pinned to `@main` (moving). |
| `fc-cache -f` | OK | |
| `npm init -y && npm i -s remotion@4 ...` in `~/motion` | OK | Resolved `remotion`/`@remotion/cli`/`@remotion/renderer` **4.0.543**, React 18.3.1. 253 MB `node_modules`. Ranges are `^4.0.543`; no lockfile kept in the repo. (`-s` is `--silent`, not `--save`.) |

Failure is silent because: no `set -euo pipefail`, curl failures are `|| true`, and the script's exit code is the last command's (npm). The wiki's open question ("does it run cleanly?") is answered: **no**.

Dry-run of the pip set **without moviepy** resolves fine in 5 s (30 packages: opencv-python-headless 5.0.0.93, librosa 1.0.1, numba 0.68.1, scipy 1.18.1, scikit-image 0.26.0, scenedetect 0.7.3, ...). Note scenedetect 0.7.3 pulls **`opencv-python` (GUI build) alongside `opencv-python-headless`** — two packages owning the same `cv2` module. `moviepy` + `pillow<12` also resolves fine on its own. (Actual install of the fixed set was blocked by the session's permission classifier, so its wall time is unmeasured; expect roughly 1–2 min for scipy/numba/llvmlite/opencv wheels.)

Reproducibility: every dependency is unpinned (pip names without versions, `remotion@4` caret, fonts `@main`, Remotion's headless shell = whatever it downloads). Script installs into system Python with `--break-system-packages`.

Not wired up: no environment has this as its setup script, so every session starts without any of it; the personal skills each run their own setup (see 2).

## 3. Repo hygiene

- **LFS**: `videos/Nazira_musiqa_bilan.mp4` and `videos/Nazira_musiqasiz.mp4` in the working tree are **134-byte LFS pointers**, not video. The container's global git config sets `filter.lfs.smudge = git-lfs smudge --skip`, so checkouts never materialise LFS files; `ffprobe` on them fails. The objects *are* on the server: in a scratch clone `git lfs fetch -I videos/Nazira_musiqasiz.mp4` pulled 146 MB in 8.5 s; the file is 1080×1920 h264 30 fps + AAC 48 kHz, 47.5 s (~24.7 Mbit/s).
- **Outputs committed as source**: `videos/` holds finished deliverables (with-music, no-music, cover JPG) — ~293 MB of LFS per reel. sohiba-opa rule 6 makes this the delivery channel (raw GitHub link). LFS storage/bandwidth quota will fill after a handful of reels; nothing documents retention.
- `.gitattributes` covers only `videos/*.mp4`. `.mov`, `.wav`, `.png`, `.jpg` (the 457 KB cover is a normal blob), anything outside `videos/` would go in as normal git blobs.
- **No `.gitignore`**: nothing stops an agent committing `node_modules/`, `.remotion/` (243 MB), `out/`, `__pycache__`, whisper models.
- **No README, no CODING_STANDARDS / CONTRIBUTING.** `CLAUDE.md` (250 bytes) only covers issue tracker and domain docs, and points to **`GLOSSARY.md` and `docs/adr/`, which do not exist**.
- **No checks**: no `.github/`, no CI, no shellcheck/lint, no smoke test, no `package.json` or `requirements.txt` in the repo.
- No defined place for work-in-progress: skills use `~/sohiba`, `~/motion/reel`, the session scratchpad, ad hoc. No convention for naming outputs (e.g. `<client>_<slug>_<variant>.mp4`).
- Wiki claims checked: "16 lines" correct; "videos/*.mp4 stored with LFS" correct.

## 4. Improvement candidates (ranked by impact)

1. **Fix the pip step so it actually installs, and make failures loud.** — Effort **S**
   - Problem: pillow>=12.2 vs moviepy 2.2.1 (`pillow<12`) conflict aborts the whole pip install; script still exits 0 (`setup.log`).
   - Fix: `set -euo pipefail`; drop moviepy (ffmpeg + Python already cover its uses; none of the skills' scripts import it) or pin `moviepy==2.2.1 pillow==11.*`; replace `scenedetect[opencv]` with `scenedetect` and uninstall/avoid `opencv-python` so only headless cv2 remains; fail on font download errors instead of `|| true`; end with a verification block (imports + `ffmpeg -version` + `fc-list` checks) that exits non-zero.

2. **Wire setup into the cloud environment (setup script) and make it idempotent.** — Effort **S**
   - Problem: no environment ("Gym", "Edit", "Nasiba Opa") has a setup script; each session re-installs ad hoc, and skills claim registries are blocked.
   - Fix: once item 1 passes, save `bash Cloud/video-setup.sh` (guarded by `[ -d Cloud ]`) as the environment setup script via `update_environment`; skip steps already done (`[ -d ~/motion/node_modules/@remotion/cli ] || ...`).

3. **Bake transcription into setup: whisper.cpp build + large-v3-q8 model with checksum.** — Effort **M**
   - Problem: every transcription-using session spends ~3 min building whisper.cpp and downloads 1.66 GB; all three reel skills need it.
   - Fix: in setup, clone whisper.cpp at a pinned tag, build `whisper-cli` to `~/opt/whisper.cpp`, download model to `~/models/` with sha256 check, put a `transcribe` wrapper on PATH (`ffmpeg → 16 kHz wav → whisper-cli -l uz -ml 1 -sow -oj`, chunked at 50 s per sohiba-opa's pitfall). Skills then call the wrapper.

4. **Use the preinstalled headless shell for Remotion (or pre-download once).** — Effort **S**
   - Problem: first render in each project dir downloads 102 MB into `<project>/.remotion` (243 MB); 17.5 s vs 5.2 s with the local browser.
   - Fix: add `remotion.config.ts` with `Config.setBrowserExecutable('/opt/pw-browsers/.../chrome-headless-shell')` in the shared project, or run `npx remotion browser ensure` once in setup; ensure `.remotion/` is in `.gitignore`.

5. **Move the Remotion project and Python helpers into the repo, with lockfiles.** — Effort **M**
   - Problem: `~/motion` is created by `npm init -y` with unpinned `^4.0.543`; sohiba-opa copies its `Reel.tsx` there; no lockfile anywhere, so a Remotion 4.x bump can silently change renders.
   - Fix: `motion/` in the repo with `package.json` (exact versions), `package-lock.json`, `remotion.config.ts`, shared components (Bg, Word, Chip, Squig...) and per-style compositions; `requirements.txt` with pinned versions; setup runs `npm ci` and `pip install -r`.

6. **Add mediapipe + libEGL + all style fonts to setup.** — Effort **S**
   - Problem: sohiba-opa needs mediapipe and `libEGL.so.1` (missing); Outfit, Inter Tight, Instrument Serif, Inter Display are fetched separately by each skill; Poppins/Bebas lack U+02BB.
   - Fix: `apt-get install -y libegl1 libgles2`, `pip install mediapipe` (pinned), download face_landmarker/selfie models to `~/models`, fetch all style fonts from a pinned google/fonts commit (not `@main`); document "use U+2019 or a font with U+02BB for oʻ/gʻ" or drop Poppins/Bebas for captions.

7. **Add `.gitignore`, broaden `.gitattributes`, and fix LFS checkout.** — Effort **S**
   - Problem: no `.gitignore`; only `videos/*.mp4` is LFS; global `smudge --skip` leaves pointers in the tree.
   - Fix: `.gitignore` for `node_modules/ .remotion/ out/ build/ *.wav models/ __pycache__/`; LFS for `*.mp4 *.mov *.wav *.jpg *.png` under `videos/` (and `assets/`); setup or README says `git lfs pull -I videos/<file>` when a past reel is needed (8.5 s for 146 MB).

8. **Decide where outputs go and how long they stay.** — Effort **S** (decision) / **M** (tooling)
   - Problem: ~293 MB LFS per reel committed to the code repo as the delivery channel; LFS quota and clone size grow with every reel.
   - Fix: document `videos/<YYYY-MM>/<client>_<slug>_<variant>.mp4` naming; deliver only the final variant + cover; consider GitHub Releases assets or an external bucket for deliverables; add a short retention rule in the wiki.

9. **README + CLAUDE.md that orient an agent in one read; fix dangling pointers.** — Effort **S**
   - Problem: no README; CLAUDE.md points to missing `GLOSSARY.md` and `docs/adr/`; nothing tells an agent that tools exist, where scratch/outputs go, or which skill to use.
   - Fix: README (what the repo is, setup, layout, delivery rule); CLAUDE.md section "Video work": run setup check, workdir convention, output convention, Remotion `--public-dir` and `--browser-executable` gotchas; create `GLOSSARY.md` (reel, cover/muqova, cut, beat, theme) or remove the pointer.

10. **Add a smoke test and minimal CI.** — Effort **M**
    - Problem: no checks; the broken pip step went unnoticed.
    - Fix: `scripts/doctor.sh` (imports, ffmpeg filters, fonts incl. U+02BB check, whisper-cli + model hash, 1-second Remotion still render); GitHub Action running shellcheck + `doctor.sh` on PRs touching setup/motion; optionally `tsc --noEmit` on the Remotion project.

11. **Consolidate the three graphics stacks and update stale skill guidance.** — Effort **L**
    - Problem: sohiba-opa = Remotion, hair-iroda-opa = HTML + Playwright screenshots, pedolog-dizayn = Python per-frame; each with its own setup and font source. Skills say PyPI/npm/HF are blocked, which is false in the current environment.
    - Fix: move the reusable pipeline steps (transcribe, cut-on-silence with re-transcribe verification, retouch, loudness/QA tile, cover pick) into repo scripts; express each style as a Remotion theme + scene list; skills shrink to style rules + "call these scripts". Update the network notes in the skills.
